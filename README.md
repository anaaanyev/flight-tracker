# Трекер авиабилетов

Следит за самой дешёвой ценой на рейсы в одну сторону (1 взрослый, эконом, прямой или с 1 пересадкой)
с датой вылета через 15–45 дней от дня проверки. По умолчанию следит за Москва → Бангкок,
маршруты (откуда и куда) меняются командами в Telegram. Пишет в Telegram только когда цена
упала ниже сохранённого минимума больше чем на порог (по умолчанию 1000 ₽).
Раз в месяц присылает короткий отчёт, что бот жив.

Следит за двумя ценами отдельно: самый дешёвый вариант (прямой или с 1 пересадкой) и самый дешёвый
прямой рейс. Уведомление приходит, если упала любая из двух. В нём обе цены и по короткой ссылке
на поиск Aviasales на дату вылета (ссылка открывает поиск, цена там может отличаться от кэша).

Работает на GitHub Actions, свой сервер не нужен.

## Установка (около 15 минут)

### 1. Telegram-бот
1. В Telegram откройте @BotFather → `/newbot` → задайте имя → скопируйте **токен**.
2. Найдите своего бота и отправьте ему `/start`.
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   и найдите `"chat":{"id": 123456789` — это ваш **chat_id**.

### 2. Токен Aviasales
1. Зарегистрируйтесь на https://www.travelpayouts.com/ (бесплатно).
2. В разделе «Инструменты» → «API» скопируйте **API-токен**.

### 3. Репозиторий
1. Создайте **публичный** репозиторий на GitHub.
2. Загрузите в него все файлы проекта (включая папку `.github`).
3. Settings → Secrets and variables → Actions → New repository secret. Добавьте три секрета:
   - `TG_TOKEN` — токен бота
   - `TG_CHAT_ID` — ваш chat_id
   - `TP_TOKEN` — токен Travelpayouts
4. Вкладка Actions → включите workflows, если GitHub попросит.
5. Actions → flight-tracker → Run workflow — первый запуск вручную.
   В Telegram придёт сообщение «Слежение запущено, базовая цена …».

Дальше всё работает само.

## Команды в Telegram

| Команда | Что делает |
|---|---|
| `/set MOW BKK` | следить за одним маршрутом (откуда, куда); остальные маршруты удаляются |
| `/add LED HKT` | добавить ещё один маршрут (до 8 штук) |
| `/remove LED HKT` | убрать маршрут |
| `/routes` | список маршрутов и их минимальные цены |
| `/threshold 1500` | порог падения цены в рублях (общий для всех маршрутов) |
| `/status` | настройки и текущие минимумы |
| `/prices` | показать текущие цены по всем маршрутам: самый дешёвый вариант и самый дешёвый прямой, со ссылками. Ничего не сохраняет и сохранённые минимумы не трогает |
| `/prices LED HKT` | то же для любого одного маршрута, без добавления его в слежение |
| `/check` | полная проверка как ежедневная (может обновить минимум и прислать уведомление о падении), бот ответит по каждому маршруту, даже если снижения нет |
| `/help` | список команд |

Коды — IATA города или аэропорта: MOW, LED, KZN, SVX, BKK, HKT, DXB и так далее.
Команды обрабатываются раз в ~15 минут (так работает расписание GitHub), ответ приходит с такой задержкой.
У каждого маршрута свой минимум, он сбрасывается при `/set` и при добавлении нового маршрута.
Минимум привязан к дате вылета. Когда эта дата выходит из окна поиска (до вылета остаётся меньше 15 дней),
бот молча заменяет минимум текущей ценой, без уведомления: такой билет он уже не найдёт, и сравнивать
с ним бессмысленно.

## Настройка в коде (tracker.py, верх файла)
`WINDOW_DAYS` — окно дат, `MAX_TRANSFERS` — пересадки,
`MAX_ROUTES` — лимит маршрутов, `DEFAULT_ROUTE` — маршрут до первой команды.
Время ежедневной проверки задаётся в `.github/workflows/tracker.yml`, строка `cron: "7 6 * * *"`
(время в UTC: 06:07 UTC = 09:07 по Москве).

## Как работает расписание и сохранение
- Каждые 15 минут: только разбор команд из Telegram. Цены в этот момент не запрашиваются.
- Раз в сутки около 09:00 МСК (и по команде `/check` или ручному запуску): проверка цен.
- Файл `state.json` коммитится только при реальных событиях: новая минимальная цена, смена маршрутов
  или порога, ежемесячный отчёт, служебный коммит раз в ~25 дней. Обычно это несколько коммитов в месяц.

## Важно
- Цены из Aviasales Data API — кэш недавних поисков, не живой поиск. Перед покупкой проверьте цену на сайте.
  Для редких направлений данных может не быть, тогда бот напишет «предложений не найдено».
- Если в репозитории 60 дней нет активности, GitHub отключает расписание. Скрипт сам делает коммит
  примерно раз в 25 дней, поэтому этого не случится.
- Время запусков GitHub может плавать на 5–20 минут.
- Если вы обновляете уже запущенный трекер, просто замените `tracker.py` и `README.md`.
  Старый `state.json` подхватится автоматически: прежний маршрут и минимум сохранятся.
